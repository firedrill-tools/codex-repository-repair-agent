# Repository repair qualification

Supported independent scope is Node20+ on POSIX with Git/npm, pinned @openai/codex-sdk0.162.1 and its public published CLI. Workspace data is synthetic; this supervisor is an application integrity/lifetime boundary, not a hostile-code OS sandbox.

The original filesystem snapshot is external to target context and binds root identity, regular-file hashes/sizes/modes and directories before any agent. Bounds:512 entries,1MiB per file,8MiB total. Only src/quote.js may change in repair mode; clarification/verification modes require zero changes. Protected source, package/test entry points, ignored/committed/assume-unchanged/newline paths, aliases/type/mode changes are checked before execution. Fresh private materialization excludes old node_modules/Git state, preserves modes and is checked with the original candidate between commands. Generated root node_modules and Git administrative files are outside business-file comparison. This is not arbitrary-race or hard read containment.

All runtime Git/npm/grader commands are asynchronous owned groups with parent cancellation, requested30-second operation budget,1MiB stdout/stderr caps and prepared/completed private journals. Provider keys and inherited npm12 allow-scripts wrapper settings are removed from validator environments. Source/recording continuity is checked before further execution. Aborted attempts can record a read-only filesystem delta without dispatching further validation.

Normal native execution uses a private Codex home/explicit key and the SDK's public codexPathOverride relay around the published pinned CLI. No fallback uses account login or a different model. Original stdout1MiB/stderr64KiB/stdin16KiB bytes/hashes/JSONL are flushed before SDK parsing; SDK events must match originals except the known absent-cache-write default. Each usage field is observed/unknown/invalid at its own source. Original missing cache-write remains unknown; SDK-inserted0 is labeled. Actual serving model, provider usage/cost and internal transport attempts remain unknown unless exposed. Failed/partial original reports survive errors.

The full bounded stream must have coherent thread/turn/item identities, a nonblank final answer, no pending work, turn.completed and clean exhaustion. Subsequent tool activity clears prior progress. Failed turns, unknown/external/trailing/replayed/malformed/oversized output, EOF and cancellation fail. Supported nonfatal error items and recovered connection diagnostics remain preserved; they do not establish completion by themselves. Unexpected external events retain unknown effects.

The process supervisor inventories host PID/PPID/PGID/state, periodically retains observed descendant groups and freezes root/jobs to obtain a stable stopped closure before TERM/CONT/KILL. Ordinary separate bundled tool sessions and their descendants are included, even after reparenting. Parent fallback inventories a stalled relay without signaling its inherited application group. Only owned groups/observed members are signaled; model stdout or namespace-local PIDs cannot authorize signals. Bounds are1024 observed members,4MiB metadata, one-second inventory deadline/two-second uncertain-exit cap, requested200ms TERM grace and up to5seconds cleanup. Defunct state, runnable state and root-group absence are distinct facts. Unknown inventory/exit fails. Arbitrary malicious escape, unobserved rapid daemonization, hard total wall time, heap, retry/traffic/billing and OS sandbox effectiveness are not guaranteed.

Actual pinned SDK/CLI and a controlled loopback HTTP/SSE provider exercise normal CLI repair/fresh validation and separate tool/grandchild cancellation without paid inference. Additional controlled executables qualify ignored signals, stalled relay, original CLI usage/errors, recording/startup faults and interruption after edits. Caller SDK/factory resources have separate ownership labels and bounded uncertain cleanup; unresolved work fails. Native promises, iterator cleanup and awaited storage complete before final receipts; filesystem/recording waits are excluded from hard wall claims.

An optional public provider base URL supports HTTPS or loopback HTTP, rejecting credentials/query/fragment before dispatch and excluding invalid URL credentials from evidence. Normal provider defaults are unchanged. Private0700 run directories/0600 atomically flushed traces preserve original source, request/command intent, SDK/CLI observations and failures. Sticky recording failure prevents subsequent verification; persistent publication failure returns failed in-memory evidence with unknown durable status.

The seven atlas-checkout-repairs1.0.0 cases/four profiles retain their original identities, hashes, customer/order facts and no-edit semantics. Historical live proof is unchanged and does not qualify this changed source. Refreshed live judgment, released Firedrill integration and publication/license remain separate gates.

Ubuntu24 native sandbox startup is a host prerequisite. CI qualifies it with a temporary AppArmor userns profile attached to the exact pinned binary, including its fresh source install. The profile helper is restricted to explicit disposable GitHub Linux CI; it changes no global sysctl and application execution never invokes it. Workflow cleanup removes the profile. Sources: [Ubuntu release notes](https://documentation.ubuntu.com/release-notes/24.04/), [upstream Codex issue](https://github.com/openai/codex/issues/14919).
